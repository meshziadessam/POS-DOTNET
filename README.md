# Push

**نظام كاشير وإدارة مطاعم باللغة العربية لنظام Windows.**

يجمع Push إدارة الطلبات والأصناف والمخزون والعملاء والتقارير وطباعة الإيصالات في تطبيق مكتبي بواجهة داكنة تدعم اتجاه الكتابة من اليمين إلى اليسار.

**الإصدار:** 1.2.3 · **التقنيات:** C# / Windows Forms / .NET Framework 4.8 / SQLite

## المميزات

- كتالوج أصناف يتكيّف مع مساحة النافذة، وبحث بالباركود.
- عرض الطلب بأعمدة لاسم الصنف والكمية والسعر والإجمالي، مع الخصومات والملاحظات.
- دعم التيك أواي والدليفري والطاولات والشركات.
- إدارة الأصناف والعملاء والمخزون والمصروفات وتقارير المبيعات.
- تسجيل الدخول قبل فتح الكاشير، مع حسابات للمدير والموظفين.
- طباعة إيصالات عربية وإعادة طباعة الطلبات السابقة.
- نسخ احتياطي واستعادة للبيانات.
- تخصيص اسم المطعم والتليفونات والعنوان وخاتمة الإيصال وصورة المطعم.
- اختيار الصورة أثناء التثبيت لتظهر داخل البرنامج وعلى الإيصال وكأيقونة ملف التشغيل.
- تسمية ملف التشغيل والاختصار باسم المطعم أثناء التثبيت، بما في ذلك الأسماء العربية.
- تفعيل دائم لجهاز واحد بملف ترخيص موقّع يعمل دون اتصال بالإنترنت.

## تثبيت نسخة العميل

1. شغّل `PushPOS-Setup.exe`.
2. أدخل اسم المطعم وبياناته، واختر صورة المطعم اختياريًا.
3. أرسل كود الجهاز الظاهر في شاشة التفعيل إلى البائع للحصول على ملف `.lic`.
4. استورد ملف التفعيل، ثم أنشئ حساب المدير وأضف الموظفين من الإعدادات.
5. اختر الطابعة من الإعدادات واختبر الإيصال قبل الاستخدام الفعلي.

قاعدة البيانات تُنشأ تلقائيًا؛ لا يحتاج العميل إلى مشروع Python أو قاعدة بيانات جاهزة. تُحفظ البيانات في `%LOCALAPPDATA%\PushPOS`، ويحتفظ إلغاء التثبيت بها.

المثبّت الكامل يتضمن مثبت .NET Framework 4.8. النسخة الصغيرة تتطلب وجود Framework 4.8 مسبقًا. تغيير صورة المطعم من الإعدادات يحدّث صورة الواجهة والإيصال؛ تضمين أيقونة ملف التشغيل يتم أثناء التثبيت.

## بناء المشروع

نفّذ الأوامر من المجلد الذي يحتوي على `RestaurantPos.sln` و`build.ps1`.

### المتطلبات

- Windows وPowerShell.
- .NET SDK يدعم بناء مشاريع .NET Framework 4.8؛ جرى البناء باستخدام SDK 10.
- اتصال بـNuGet لاستعادة الحزم عند البناء لأول مرة.
- Inno Setup **6.4.3** عند تجهيز المثبّت.

لبناء التطبيق وأداة تخصيص الأيقونة وأداة البائع والاختبارات:

```powershell
./build.ps1
```

ملف التطبيق الناتج:

```text
src/RestaurantPos/bin/Release/net48/RestaurantPos.exe
```

الاسم الداخلي للمشروع هو `RestaurantPos`، والاسم المعروض للمستخدم هو **Push**. يخصّص المثبّت اسم الملف وفق اسم المطعم.

### تجهيز المثبّت

لإنشاء النسخة الصغيرة:

```powershell
./build.ps1 -InnoCompiler 'C:\Program Files (x86)\Inno Setup 6\ISCC.exe'
```

لإنشاء النسخة الكاملة، ضع مثبت Microsoft الأصلي `ndp48-x86-x64-allos-enu.exe` داخل `.tools/`، ثم نفّذ:

```powershell
./build.ps1 -InnoCompiler 'C:\Program Files (x86)\Inno Setup 6\ISCC.exe' -BundleFramework
```

يتحقق سكربت البناء من توقيع Microsoft لمثبت Framework. يمكن تمرير مسار محلي آخر لـ`ISCC.exe`. أدوات `.tools/` مستبعدة من Git ويجب توفيرها عند البناء من نسخة مستنسخة من المستودع.

المخرجات داخل `artifacts/`:

| الملف | الاستخدام |
| --- | --- |
| `PushPOS-Setup.exe` | مثبّت العميل الكامل |
| `PushPOS-Setup-Small.exe` | مثبّت العميل دون Framework |

السكربت الاختياري `tools/package_release.py` يجمّع أرشيفات المصدر وأدوات البائع ويحسب SHA-256 للمخرجات، ويتطلب Python 3. تطبيق الكاشير نفسه لا يعتمد على Python.

## الاختبارات

بعد البناء، لتشغيل اختبارات التشغيل والواجهات:

```powershell
./tests/OperationalChecks/bin/Release/net48/OperationalChecks.exe ./qa-output
```

ولتشغيل اختبارات الأداء:

```powershell
./tests/PerformanceChecks/bin/Release/net48/PerformanceChecks.exe ./performance-output
```

تستخدم الاختبارات بيانات تجريبية مستقلة. آخر تحقق بعد تنظيف المشروع: **170 اختبار تشغيل وإصدار ناجحًا**، تشمل البيع والمخزون والصلاحيات والتقارير والنسخ الاحتياطي والاستعادة والواجهات. تُراجع الطباعة الفعلية على طابعة العميل ضمن اختبار التسليم.

## التراخيص وملفات GitHub

يحتوي المصدر على **المفتاح العام فقط** للتحقق من تراخيص RSA-4096 / SHA-256. مفتاح الإصدار الخاص يبقى خارج المستودع. يجب الحفاظ على نفس زوج المفاتيح عبر التحديثات لتظل تراخيص العملاء متوافقة.

ملف `.gitignore` يستبعد مخرجات البناء وقواعد البيانات والتفعيلات والمفاتيح الخاصة. لا ترفع `issuer-private.xml` أو ملفات `.lic` أو بيانات العملاء أو أرشيفات أدوات البائع إلى مستودع عام. استخدم مستودعًا خاصًا للمصدر التجاري، وأرسل المثبّت فقط للعميل. يمكن إرفاق مثبّت العميل في GitHub Releases عند الحاجة.

التفعيل دون اتصال يرفض ترخيص جهاز آخر، لكنه لا يوفر إلغاءً عن بُعد أو حماية مطلقة من تعديل البرنامج. توقيع ملف الترخيص مستقل عن توقيع ناشر Windows؛ ملفات التنفيذ الحالية لا تحمل شهادة Authenticode تجارية.
